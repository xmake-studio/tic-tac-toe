
## REST API

API позволяет создать игру, получить её состояние и сделать ход против программы.
Базовый адрес при локальном запуске сервера: `http://localhost:8008`.
HTTP-сервер реализован в ветке `server`; в ветке `apispec` описывается его контракт.

### Перечень эндпоинтов

| Действие | URL | Метод | Описание запроса и ответа |
| --- | --- | --- | --- |
| Создать игру | `/games` | `POST` | Без тела запроса. Возвращает `201 Created`, идентификатор, пустое поле и статус новой игры. |
| Получить состояние игры | `/games/{game_id}` | `GET` | Идентификатор передаётся в URL. Возвращает `200 OK`, поле и текущий статус игры. |
| Сделать ход | `/games/{game_id}/moves` | `POST` | Принимает JSON с `row` и `col`. Возвращает `200 OK`, поле после ходов, статус и координаты ответного хода программы либо `null`. |

### Общие правила взаимодействия

- Для запроса с телом используется `Content-Type: application/json`. Успешные ответы и описанные ниже ошибки приложения возвращаются в JSON.
- Авторизация не требуется. Параметры строки запроса не используются.
- Поле имеет размер 3 × 3. Координаты задаются целыми числами от `0` до `2`: `row` — строка сверху вниз, `col` — столбец слева направо. Клетка `(0, 0)` находится слева сверху, `(2, 2)` — справа снизу.
- Поле передаётся как массив из трёх строк: к клетке обращаются как `board[row][col]`. Значения: `"X"` — пользователь, `"O"` — программа, `null` — пустая клетка.
- Пользователь всегда играет `X` и ходит первым. Программа играет `O`: если может выиграть одним ходом, делает выигрышный ход; иначе выбирает случайную свободную клетку.
- Побеждает тот, кто первым собрал три своих символа в строке, столбце или диагонали. Если поле заполнено и победителя нет, объявляется ничья.
- Один запрос хода выполняет ход пользователя и, если игра продолжается, ответный ход программы. Ответ содержит итоговое состояние после этих действий.
- Если пользователь своим ходом победил или завершил игру вничью, программа не ходит; `bot_move` возвращается как `null`.
- При описанных ошибках запроса состояние игры не изменяется, программа не делает ход.

#### Поля успешного ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | string | Идентификатор игры, созданный сервером: UUID без дефисов, 32 шестнадцатеричных символа. Используется как `{game_id}` в URL. |
| `board` | array | Массив 3 × 3 со значениями `"X"`, `"O"` или `null`. |
| `status` | string | Текущее состояние и результат игры; значения приведены ниже. |
| `bot_move` | object или null | Только в ответе на ход: объект с целыми `row` и `col` либо `null`, если ответный ход не выполнялся. При создании и получении игры это поле отсутствует. |

| Статус | Значение |
| --- | --- |
| `in_progress` | Игра продолжается, можно отправлять следующий ход пользователя. |
| `player_won` | Пользователь победил. |
| `bot_won` | Программа победила. |
| `draw` | Ничья. |

### Создать игру — `POST /games`

Создаёт новую независимую партию с пустым полем. Входные параметры отсутствуют, тело запроса не требуется. Размер поля и символ пользователя не настраиваются.

Пример запроса:

```http
POST /games HTTP/1.1
Host: localhost:8008
```

Ответ: **`201 Created`**.

```json
{
  "id": "4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182",
  "board": [
    [null, null, null],
    [null, null, null],
    [null, null, null]
  ],
  "status": "in_progress"
}
```

Сохраните `id` из ответа для последующих запросов. Повторный `POST /games` создаёт другую игру.

### Получить состояние игры — `GET /games/{game_id}`

Возвращает текущее состояние существующей игры, в том числе завершённой. Не изменяет поле и не запускает ход программы.

| Параметр | Где передаётся | Тип | Обязательный | Допустимые значения |
| --- | --- | --- | --- | --- |
| `game_id` | Путь URL | string | Да | Идентификатор, полученный при создании игры. |

Тело запроса отсутствует.

Пример запроса:

```http
GET /games/4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182 HTTP/1.1
Host: localhost:8008
```

Ответ: **`200 OK`**. Пример состояния после первого хода пользователя и ответа программы:

```json
{
  "id": "4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182",
  "board": [
    ["X", null, null],
    [null, "O", null],
    [null, null, null]
  ],
  "status": "in_progress"
}
```

Если игра не найдена, возвращается **`404 Not Found`** с телом `{"error": "Игра не найдена"}`.

### Сделать ход — `POST /games/{game_id}/moves`

Ставит `X` в выбранную свободную клетку и выполняет ответный ход программы, если игра ещё не завершена.

| Параметр | Где передаётся | Тип | Обязательный | Допустимые значения |
| --- | --- | --- | --- | --- |
| `game_id` | Путь URL | string | Да | Идентификатор существующей игры. |
| `row` | Тело JSON | integer | Да | `0`, `1` или `2`. |
| `col` | Тело JSON | integer | Да | `0`, `1` или `2`. |

Тело должно быть JSON-объектом. Строки (`"1"`), дробные числа (`1.0`), логические значения (`true`, `false`) и `null` вместо координат не допускаются. Дополнительные поля текущая реализация игнорирует.

Пример первого хода в новой игре:

```http
POST /games/4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182/moves HTTP/1.1
Host: localhost:8008
Content-Type: application/json

{"row": 0, "col": 0}
```

Ответ: **`200 OK`**.

```json
{
  "id": "4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182",
  "board": [
    ["X", null, null],
    [null, "O", null],
    [null, null, null]
  ],
  "status": "in_progress",
  "bot_move": {"row": 1, "col": 1}
}
```

Ответный ход в примере условный: из-за случайного выбора программа может занять другую свободную клетку.

#### Если ход пользователя завершил игру

Например, до запроса поле было `[["X", "X", null], ["O", "O", null], [null, null, null]]`.
Пользователь отправляет `{"row": 0, "col": 2}` и побеждает.

Ответ: **`200 OK`**.

```json
{
  "id": "4f1c2b7e8a9d4c1f9b2e6a0d3c5f7182",
  "board": [
    ["X", "X", "X"],
    ["O", "O", null],
    [null, null, null]
  ],
  "status": "player_won",
  "bot_move": null
}
```

При ничьей после хода пользователя возвращаются `status: "draw"` и `bot_move: null`.
Если выиграла программа, возвращаются `status: "bot_won"` и координаты её выигрышного хода в `bot_move`.
Завершение партии — успешный результат запроса с кодом `200`, а не ошибка.

### Коды ответа и ошибки

| HTTP-код | Когда возвращается | Тело ошибки |
| --- | --- | --- |
| `201 Created` | Новая игра создана. | — |
| `200 OK` | Состояние получено или ход выполнен, в том числе завершивший игру. | — |
| `400 Bad Request` | В запросе хода отсутствует тело, JSON повреждён, передан не объект либо не указан подходящий `Content-Type`. | `{"error": "Тело запроса должно быть JSON-объектом"}` |
| `400 Bad Request` | Отсутствует `row` или `col` либо значение не является целым числом. | `{"error": "Нужно передать целые row и col"}` |
| `400 Bad Request` | Координаты выходят за диапазон `0–2`. | `{"error": "Координаты вне поля"}` |
| `400 Bad Request` | Выбранная клетка уже занята. | `{"error": "Клетка уже занята"}` |
| `404 Not Found` | Игра с указанным идентификатором не найдена при получении состояния или отправке хода. | `{"error": "Игра не найдена"}` |
| `409 Conflict` | Попытка сделать ход в завершённой игре. | `{"error": "Игра уже закончена"}` |

Формат описанных ошибок приложения — JSON-объект с единственным строковым полем `error`:

```json
{
  "error": "Клетка уже занята"
}
```

Для запроса хода проверки выполняются в следующем порядке: наличие игры → формат тела и типы координат → завершённость игры → диапазон координат и занятость клетки. Если запрос содержит несколько ошибок, возвращается первая обнаруженная. Например, для неизвестной игры возвращается `404` даже при неверном теле запроса; для завершённой игры с целыми координатами — `409`.

Таблица описывает ошибки обработчиков API. Для неизвестных URL и неподдерживаемых методов Flask может вернуть стандартный HTML-ответ `404` или `405`; единый JSON-формат для таких ответов текущая реализация не задаёт.
